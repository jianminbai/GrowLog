# GrowLog 移动端优先 UI 审计与优化设计

- 日期：2026-10-22
- 状态：已由用户确认
- 范围：受保护应用界面、登录页及相关交互样式；不改变 API、数据库模型或业务规则

## 1. 背景与目标

GrowLog 的主要运行终端是手机，核心使用者是需要在日常照护间隙快速完成记录的家长。现有 MVP 已具备完整业务能力和移动优先的基础样式，但导航、表单密度、触控尺寸、窄屏信息层级和部分无障碍细节仍更接近响应式桌面页面。

本轮优化以“单手快速记录”为首要场景，在不重写业务逻辑的前提下完成统一的移动应用外壳、录入流程和视觉规范。成功标准是用户在 320–430px 宽度的手机上可以清楚理解当前页面，用拇指到达主要操作，并以尽量少的滚动和判断完成一条日常记录。

## 2. 审计结论

### 高优先级问题

1. 受保护区域使用横向顶部导航，四个入口在窄屏容易拥挤，没有当前页状态，也没有可见的退出登录入口。
2. 表单控件继承约 13.6px 字号，低于 iOS 防自动缩放所需的 16px；按钮和链接没有统一的 44px 最小触控尺寸。
3. 生长、睡眠、饮食、活动和情绪页面把必填项、低频可选项和历史记录放在同一条长页面中，高频录入的首屏成本偏高。
4. 页面标题最小接近 45–48px，配合宽顶部留白，在小屏上占用过多首屏空间。
5. 日期标签、Dashboard 双列内容、历史记录左右布局和儿童详情页的五个行内按钮在 320–375px 宽度容易挤压或形成不规则换行。
6. 删除记录直接执行，没有移动端误触确认。

### 中优先级问题

1. 快捷操作横向滚动，但缺少滚动提示、吸附和触控反馈。
2. 成功、错误和处理中状态的语义不一致，部分消息缺少 `role="status"` 或 `role="alert"`。
3. 深色模式中的浅色完成状态卡沿用浅色背景，但文字继承浅色主题前景色，存在对比度风险。
4. 页面没有使用 `env(safe-area-inset-*)`，安装为 PWA 后底部导航和操作可能贴近系统手势区。
5. 历史卡片展开后直接展示完整编辑表单，信息密度高，危险操作与主要提交操作距离较近。
6. 中英文 eyebrow 文案混用，对手机用户没有提供额外信息。

### 已有优势

- HTML 表单标签、主要 section 标题和服务端渲染基础较好。
- 数据缺失与零值已正确区分，健康表述克制。
- 页面路由和业务领域边界清晰，可以只重构展示层。
- 现有 PWA、认证、CSRF、软删除和审计能力可以直接复用。

## 3. 设计原则

1. **拇指可达**：手机主导航和高频提交操作位于屏幕下半部；主要触控目标至少 44×44px。
2. **先完成，再补充**：默认只展示完成一条记录所需的字段，低频字段放入“更多信息”。
3. **一屏一个主任务**：页面标题、摘要、快速录入和历史记录按优先级分层，不在首屏竞争注意力。
4. **信息真实**：保留现有未知值、医学边界和描述性趋势原则，不为了视觉完整而制造数据。
5. **渐进增强**：无 JavaScript 时仍保留可理解的语义结构；不增加大型 UI 或图标依赖。
6. **桌面可用**：手机是主要目标，760px 以上继续提供适度扩展布局，不形成独立桌面产品。

## 4. 信息架构与应用外壳

### 手机端

受保护区域使用固定底部导航，包含四个等宽入口：

- 今天：`/today`
- 历史：`/history`
- 档案：`/children` 及其子路由
- 设置：`/settings`

每个入口同时显示简洁图形和文字标签；当前入口使用 `aria-current="page"`、颜色和背景三重提示。底部高度包含 `safe-area-inset-bottom`，页面内容增加对应的底部留白。

顶部改为轻量上下文栏：左侧品牌或返回操作，右侧只放当前页面必要动作。领域子页面保留明确的返回儿童档案入口，但缩短文案并保证 44px 触控高度。

### 较宽屏幕

760px 以上继续显示顶部导航，隐藏固定底部导航。内容最大宽度按页面类型控制：记录与表单页面约 44rem，Dashboard 和公开首页可以更宽。

### 导航状态

新增一个小型客户端导航组件，仅使用 `usePathname` 判断当前路由。导航不读取健康数据，不改变服务端页面的数据加载方式。

## 5. 页面设计

### 5.1 登录页

- 手机首屏优先显示品牌、登录标题和表单，说明文字缩短并移至表单后。
- 邮箱和密码输入高度至少 48px、字号 16px。
- 提交按钮占满手机内容宽度，清楚显示处理中状态。
- 错误使用 `role="alert"`，输入错误时保持用户已填写的邮箱。

### 5.2 今日 Dashboard

- 标题压缩为“今天”，日期作为次要信息，不在窄屏与标题并排。
- 每个儿童卡片首先显示四个录入状态入口；待记录项使用更明确的主色轮廓，已记录项使用低强调完成状态。
- 快捷录入保持横向列表，增加滚动吸附和末端留白；第一个常用操作完整可见，后续操作露出边缘提示可横滑。
- 最近指标采用单列紧凑列表，避免双列中的长文本挤压。
- 描述性趋势默认保持低强调，位于录入状态和指标之后。

### 5.3 儿童档案列表与详情

- 已有儿童卡片放在新建表单之前。
- 儿童详情页的五个领域入口改为 2 列功能网格；每项包含短标题和明确触控区域，不继续使用连续行内胶囊按钮。
- 基础资料编辑按“基本信息、出生信息、家庭信息、备注”分组；它是低频任务，可以保留完整字段，但组间层级要清楚。

### 5.4 领域记录页

所有领域页面使用一致顺序：

1. 紧凑返回栏与页面标题
2. 关键摘要（如有）
3. 快速新增记录
4. 历史记录
5. 已删除记录（仅存在时）

新增表单默认展示的字段：

| 领域 | 默认字段 | “更多信息”字段 |
| --- | --- | --- |
| 生长 | 时间、身高、体重、来源 | 头围、地点、方法、设备、精度说明、备注 |
| 睡眠 | 类型、开始、结束 | 清醒分钟、醒来次数、来源、备注 |
| 餐食 | 餐次、时间、食物名称、摄入量 | 分类、提供量、估算量、单位、新食物、反应、食欲、备注、来源 |
| 饮品 | 类型、时间、容量 | 备注、来源 |
| 活动 | 类型、总时长、户外时长、强度、时间 | 组织形式、参与表现、来源、备注 |
| 情绪 | 总体情绪、时间、标签 | 持续时间、情境、同伴互动、亲子互动、来源、备注 |

原生 `<details>` 用于“更多信息”，保证无额外 JavaScript 也可操作。编辑已有记录时自动展示已填写的可选字段，避免隐藏现有内容。

手机上的主要提交按钮占满宽度。编辑表单的删除按钮与保存按钮分开呈现；删除前显示原生确认对话或等价的轻量确认步骤，文案明确记录类型和不可在当前步骤硬删除。

### 5.5 历史与审计

- 历史记录卡在手机上改为上下布局：类型与标题在上，时间和动作提示在下。
- “查看已删除记录”使用清晰的筛选控件样式，并显示当前筛选状态。
- 审计事件降低视觉权重，避免与健康记录竞争；长字段列表允许换行。

### 5.6 设置

- 保留 JSON 和 CSV 导出。
- 增加独立“账户”区域与退出登录按钮。
- 退出时复用现有 `/api/auth/logout`、CSRF cookie 和撤销会话逻辑；成功后跳转登录页。
- 数据导出按钮在手机上使用纵向全宽布局，避免小尺寸胶囊链接。

## 6. 视觉与响应式规范

在现有暖色、低医疗化视觉基础上扩展设计变量：

- 内容水平边距：手机 16px，较大手机 20px，桌面 24px。
- 正文最小字号：16px；辅助信息不低于 12px，并保证颜色对比度。
- 输入控件：最小高度 48px、字号 16px、圆角 12–14px。
- 主按钮：最小高度 48px；手机默认全宽。
- 普通可点击项：最小高度 44px。
- 页面主标题：手机约 32–36px，不再使用公开首页的超大标题尺度。
- 卡片圆角：16–20px；减少移动页面大面积阴影，主要依靠边框和背景层次。
- 焦点：所有链接、按钮和表单控件使用一致且明显的 `:focus-visible`。
- 动效：仅使用短暂颜色和位移反馈，并遵守 `prefers-reduced-motion`。
- 深色模式：状态卡定义独立的前景色，不依赖全局文字颜色；正文和控件达到 WCAG AA 对比目标。

关键断点：

- 320–430px：主要验收区间，单列和底部导航。
- 431–759px：较宽手机或小平板，仍使用移动导航。
- 760px 以上：顶部导航与双列表单布局。

## 7. 组件与代码边界

计划新增或调整的展示层边界：

- `MobileAppNav`：路径匹配、移动/桌面导航语义和当前页状态。
- `LogoutButton`：客户端退出请求、状态反馈与跳转。
- `FormSection` / `OptionalFields`：表单分组和原生渐进展开，不拥有业务数据。
- 共享 CSS 表单与按钮类：统一尺寸、焦点、禁用、危险操作和安全区。

保留各领域表单当前的请求构造和 API 路径。可以抽取纯展示组件，但不在本轮重写仓库层、校验 schema 或领域计算。这样移动端改动与业务正确性保持隔离。

现有页面中压缩为单行的 TSX 在修改涉及的文件内恢复为可读结构，便于代码审核；不进行无关后端重构。

## 8. 状态、错误与危险操作

- 提交期间禁用相关按钮并显示领域明确的“正在保存…”文案。
- 成功信息使用 `role="status"`，错误信息使用 `role="alert"`。
- 网络和 API 错误保留当前通用安全文案，不显示响应内部细节。
- 删除需要二次确认；取消确认不发送请求。
- 恢复操作保持一步完成，因为它可逆且不会丢失数据。
- 底部导航和页面操作不得遮挡表单消息、最后一个输入框或浏览器键盘上方的提交区域。

## 9. 性能与隐私

- 不增加第三方 UI、图标或动画依赖。
- 主要页面继续使用服务端组件；只有导航状态、表单和退出按钮进入客户端 bundle。
- 不在浏览器存储中保存健康表单草稿、导出数据或认证信息。
- Service Worker 缓存边界保持不变。

## 10. 验证策略

### 自动化

- 新增导航测试：四个入口、当前页 `aria-current`、移动与桌面结构。
- 新增退出测试：CSRF 请求、处理中状态、成功跳转和失败提示。
- 扩充代表性表单测试：必填字段在默认层、可选字段在 `<details>`、错误/成功状态语义、删除确认。
- 保留并运行全部领域、数据库、认证、导出和 PWA 测试。
- 运行 `npm run lint`、`npm run typecheck` 和 `npm run build`。

### 视口审查

在 320×568、375×667、390×844、430×932 和 768×1024 视口检查：

- 无页面级横向滚动。
- 底部导航不遮挡内容，并避开安全区。
- 所有主操作可见且触控区域不小于 44px。
- 输入聚焦不会因字号过小触发页面缩放。
- Dashboard、日期、历史条目和长中文文案正确换行。
- 亮色与深色状态卡文字清晰。

## 11. 验收标准

1. 320–430px 宽度下所有受保护页面无非预期水平溢出。
2. 手机端固定显示四项底部导航，当前页具有程序化和视觉状态；760px 以上切换为顶部导航。
3. 手机表单输入不小于 16px，交互目标不小于 44px，主要提交按钮不小于 48px。
4. 六类高频记录表单首屏只显示默认字段，可选字段可展开；编辑时不会隐藏已有可选内容。
5. 删除操作必须确认，恢复保持直接可用。
6. 设置页能够安全退出登录并撤销会话。
7. Dashboard 和儿童详情的高频入口可在单手拇指区域访问，且不依赖水平精确点击。
8. 成功、错误和处理中状态具有一致文案和可访问语义。
9. 亮色和深色模式下正文、状态卡、表单和导航保持清晰对比。
10. 现有业务行为、数据库隔离、导出、PWA 和安全策略不变；完整测试、类型检查、Lint 和生产构建通过。

## 12. 非目标

- 不新增儿童切换器或其他业务能力。
- 不新增医学建议、百分位或健康评分。
- 不重写 API、Prisma schema、认证协议或审计数据。
- 不增加推送通知、离线数据录入或本地健康数据缓存。
- 不为桌面端创建独立信息架构。
