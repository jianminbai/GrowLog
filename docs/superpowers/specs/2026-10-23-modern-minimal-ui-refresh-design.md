# GrowLog 现代极简移动端视觉升级设计

- 日期：2026-10-23
- 状态：已由用户确认
- 选定方向：全站平衡式重构
- 参考特征：近白背景、紫色主品牌、轻边框、弱阴影、圆角卡片、胶囊控件、线性图标、紧凑底部导航

## 1. 意图

GrowLog 已具备完整的移动端信息架构和业务能力，但现有暖米色、绿色品牌、衬线大标题与渐变背景形成了偏“生活记录册”的视觉气质。用户给出的参考界面更接近现代移动服务应用：界面明亮、留白清楚、结构紧凑，紫色用于品牌和当前状态，内容依靠白色表面、浅灰分隔和简洁图标建立层级。

本轮把这种视觉语言应用到 GrowLog 全部移动端页面，包括公开首页、登录、今天、足迹、趋势、设置、记录报告、数据管理和所有录入/编辑表单。业务流程、信息内容和健康数据语义保持不变。

## 2. 目标与成功标准

1. 四个主页签与所有子页面看起来属于同一套原生移动应用。
2. 手机首屏更轻、更紧凑，主要标题、核心卡片和首要操作能快速被识别。
3. 紫色承担品牌、主按钮、当前导航、选中态和图表主线；绿色、橙色、红色继续分别表达完成、提醒和危险。
4. 表单、历史卡片、设置菜单和报告表格使用一致的表面、圆角、边框、间距与焦点状态。
5. 320–430px 无页面级横向溢出，交互目标仍满足 44px/48px 规则，亮色和暗色模式达到 WCAG AA 对比目标。

## 3. 非目标与反目标

- 不复制参考图中的地图、服务人员、商品图片或预约业务结构。
- 不为了视觉相似而删减 GrowLog 已验证的数据字段、未知值表达、审计能力或健康边界说明。
- 不修改 API、Prisma schema、认证、CSRF、家庭隔离、软删除、导出或 PWA 缓存策略。
- 不引入大型 UI 框架、图标库、网络字体或远程图片资源。
- 不把完成、提醒和删除全部改成紫色；颜色必须继续传达业务语义。
- 不创建与移动端不同的信息架构；桌面只做自然扩展。

## 4. 考虑过的方案

### 方案 A：保守换肤

只替换颜色、字体、圆角和阴影，保留当前卡片与页面结构。优点是改动小、回归成本低；缺点是原有大标题、较重背景和不同组件密度仍会保留，与参考风格接近度有限。

### 方案 B：平衡式重构（已选择）

建立新的全局视觉令牌，在不改变业务流程的前提下重排标题、导航、卡片、表格和表单的视觉层级。大部分改动由共享 CSS 和现有语义 class 承担，仅在结构无法表达新层级时调整少量 TSX。它能明显接近参考图，同时保持测试边界和服务端组件结构稳定。

### 方案 C：高还原重构

大量使用图片化卡片、装饰插图、重构后的首页模块和更强的展示动效。视觉接近度最高，但会让健康记录界面变得像服务市场，增加内容维护、性能与可访问性成本，不适合当前产品。

## 5. 视觉系统

### 5.1 颜色

亮色模式建议令牌：

| 用途 | 色值 | 使用位置 |
| --- | --- | --- |
| 页面背景 | `#F7F7FA` | 页面底色、表格交替行 |
| 主表面 | `#FFFFFF` | 卡片、导航、表单、弹出内容 |
| 次级表面 | `#F3F0F6` | 选中态、标签、图标底色 |
| 主文字 | `#211D26` | 标题、重要数值 |
| 次文字 | `#77717D` | 描述、时间、单位 |
| 分隔线 | `#E9E6ED` | 边框、列表分隔 |
| 品牌紫 | `#76558F` | 主按钮、当前导航、链接、图表主线 |
| 深品牌紫 | `#5E3F76` | 按压态、白底上的小文字 |
| 完成绿 | `#2F8064` | 已完成状态 |
| 提醒橙 | `#C86A2B` | 待记录、注意信息 |
| 危险红 | `#B94747` | 删除、错误 |

品牌与状态使用独立变量：`--brand-violet`、`--brand-violet-strong`、`--success-green`、`--warning-orange`、`--danger-red`，不再用当前含义模糊的 `--green` 同时承担品牌与成功状态。迁移期间可以短暂保留兼容别名，最终样式与契约测试必须引用明确语义的变量。

语义状态必须成对定义前景与背景，建议亮色模式为：成功 `#E9F5F0` / `#256A52`，提醒 `#FFF1E7` / `#7A3B15`，危险 `#FDECEC` / `#963A3A`，品牌浅底 `#F1EAF5` / `#5E3F76`。`#C86A2B` 只作为提醒图标、边框或大号强调色，不直接作为白底小字号正文。暗色模式建议使用成功 `#1E3B32` / `#A8DCC8`，提醒 `#412B1D` / `#FFC49B`，危险 `#452628` / `#FFB3B3`，品牌浅底 `#30273A` / `#D8C0E8`。不采用纯黑/纯白，并逐对验证对比度。

### 5.2 排版

- 全站使用系统无衬线字体；移除页面标题与品牌中的 Georgia。
- 移动端页面主标题 30–34px、700–750 字重，紧凑行高；公开首页可使用 40–48px。
- 区块标题 16–20px；卡片标题 14–16px；辅助信息 12–13px。
- 重要数值采用 700–800 字重，不额外使用装饰字体。
- 中英文不使用强制大写或过宽字距，eyebrow 只保留在确实提供上下文的页面。

### 5.3 间距、圆角与阴影

- 基础间距采用 4/8/12/16/24/32px 阶梯。
- 手机内容边距 16px，较宽屏 20–24px。
- 输入和小控件圆角 12px；列表与普通卡片 16px；重点面板 20px；胶囊按钮使用 999px。
- 默认卡片以 `1px` 浅边框建立层级，阴影限制为 `0 8px 24px rgba(44, 34, 52, 0.06)`；禁止多层重阴影和大面积渐变。
- 区块间距由 24px 建立，卡片内部通常使用 12–16px。

## 6. 应用外壳与导航

### 手机底部导航

- 保留“今天、足迹、趋势、设置”四项结构和现有线性 SVG 图标。
- 导航表面改为白色/深色表面，顶部细边框与很弱的上投影。
- 当前项使用浅紫圆角底、品牌紫图标和文字；非当前项使用中性灰。
- 每项继续保持至少 52px 高并包含安全区，不以颜色作为唯一当前状态提示。
- 趋势领域入口和设置菜单中现有的单字/符号图标改为一组共享的小型内联 SVG，与底部导航保持一致线宽和圆角端点；不增加图标依赖。

### 桌面顶部导航

- 使用白色细边框栏和紧凑品牌字标。
- 当前链接使用浅紫胶囊背景；桌面宽度不引入新的侧边栏。

### 页面外壳

- 移除绿色径向渐变与米色纸张感，改为稳定的浅灰页面底色。
- 受保护页面宽度继续按内容类型限制；表单/报告约 44rem，Dashboard 可更宽。
- 顶部标题区不再模拟大型海报，采用标题、上下文和必要动作的紧凑组合。

## 7. 页面与组件设计

### 7.1 公开首页与登录

- 首页使用明确的品牌标题、短说明和紫色主按钮；示例数据卡变为白色轻边框卡片。
- 登录页以单个白色面板为视觉中心，输入框使用浅灰底或白底细边框，聚焦时显示紫色边框和柔和光环。
- 登录说明保持低权重，不增加插画和远程资源。

### 7.2 今天

- 日期作为小型次级文本；儿童名称与“查看档案”形成紧凑卡片头。
- 完成状态保持两列，但改为浅表面小卡：完成用绿，待记录用橙，卡片不使用大面积饱和色。
- 今日/7天/2周/1个月继续一整行四列；品牌紫用于数值，细分隔线用于列关系。
- 快捷记录使用紫色描边/浅紫胶囊，首个操作清楚可见并保留横向滚动。

### 7.3 足迹

- 日期标题与记录数量使用更轻的排版，不增加大面积 hero 渐变。
- 记录行使用白色卡片、细边框和左侧领域色短标记；标题黑色、类别/儿童/值为次级灰。
- 继续保持紧凑只读模式，不恢复时间、滑动编辑或行内操作。

### 7.4 趋势与报告

- 儿童选择卡改为简洁白卡，使用圆形/方形浅紫标识和右箭头，不依赖照片。
- 五个领域入口使用统一的小图标块、标题和描述，品牌紫表达可进入性。
- 图表卡使用白色表面，主折线改为紫色，辅助网格更淡；提示气泡使用深文字表面。
- 表格继续在自身容器内滚动，表头浅紫灰、边框更细；测量表既有居中和 53px 行高规则保留。

### 7.5 设置与数据管理

- 设置维持分组菜单结构，图标块改为浅紫底与紫色文字。
- 菜单列表使用白色整组卡片，行间用细分隔线，不给每行独立重阴影。
- 数据备份 disclosure、账户卡和恢复控件使用同一圆角/边框系统。
- 删除与错误保持红色；恢复操作使用紫色或中性描边，不误用绿色表示成功前状态。

### 7.6 表单与历史编辑

- 表单面板、历史 `<details>` 卡和可选字段 disclosure 使用一致白色表面。
- 输入、选择、文本域统一 48px 最小高度、16px 字号、12px 圆角；聚焦使用紫色边框与可见 focus ring。
- 主提交按钮使用实心紫色；次要按钮使用紫色描边；删除按钮使用红色文字/边框并与提交按钮拉开层级。
- 复选框与原生控件通过 `accent-color` 使用品牌紫。
- 展开的历史表单不改变现有保存、删除、恢复和 CSRF 流程。

### 7.7 状态与领域色

- 品牌紫只表达品牌、导航、链接、选择与主操作。
- 完成绿只表达已经完成或成功。
- 提醒橙只表达待录、注意和当前需要处理的状态。
- 危险红只表达错误与破坏性操作。
- 睡眠、营养、活动、情绪等领域可以保留低饱和辅助色用于小标记，不作为全卡背景。

## 8. 交互与无障碍

- 保留所有现有 `aria-current`、landmark、表格标题、图表可访问名称和状态消息。
- 链接、按钮、summary 最小触控目标 44px；主要表单按钮至少 48px。
- `:focus-visible` 使用高对比紫色外框，并与错误红区分。
- 只使用 120–180ms 的颜色、阴影或轻微位移反馈；`prefers-reduced-motion` 下关闭非必要动画。
- 不通过 hover 才显示必要信息；触摸与键盘功能保持完整。
- 暗色模式、完成/提醒/危险状态和主按钮均单独验证对比度。

## 9. 实现边界

优先通过 `src/app/globals.css` 重建视觉令牌与共享组件样式。现有 class 已覆盖导航、页面标题、卡片、快照、表单、历史、报告、设置和数据管理，可以避免大规模重写 JSX。实现时直接整理和合并现有选择器，删除被取代的旧规则，不在文件末尾增加一层全站覆盖样式；相应更新依赖旧 `--brand-green` 等变量名的 CSS 契约测试。

允许的少量结构改动：

- 为需要独立视觉语义的卡片或标题增加展示 class。
- 为设置/趋势入口统一图标容器和文案层级。
- 为公开首页和登录页调整不影响业务的布局包装。

不修改仓库层、领域计算、Route Handler、数据库模型和数据加载策略。不增加第三方运行时依赖。

## 10. 验证策略

### 自动化

- 先扩展 CSS/结构契约测试，验证紫色品牌令牌、无衬线标题、导航当前态、白色表面、表单焦点、语义状态色和暗色令牌。
- 保留并更新已有页面测试，确保文案、链接、表单、图表、表格和无障碍语义不因视觉升级丢失。
- 运行 `npm run lint`、`npm run typecheck`、完整 `npm test` 和 `npm run build`。

### 浏览器验收

在 320×568、390×844、430×932 和 768×1024 下检查：

- 公开首页、登录、无儿童空状态、已填充的今天、足迹和四个主页签。
- 儿童详情、五类趋势报告、五类记录表单（展开可选字段）、设置首页和数据管理。
- 无页面级横向溢出，底部导航不遮挡内容，表格只在容器内滚动。
- 主要卡片的圆角、边框、背景和间距一致。
- 输入为 16px、触控目标符合尺寸、焦点清楚。
- 当前导航为紫色浅底；完成、提醒、错误仍能一眼区分。
- 上述代表页面分别在亮色与暗色模式下检查文字、按钮、状态卡、图表和焦点状态。

## 11. 验收标准

1. 全部页面使用同一套紫色品牌与中性表面令牌，绿色/橙色/红色语义不被混淆。
2. 页面标题与品牌改用现代无衬线排版，移动端层级紧凑。
3. 底部导航、桌面导航、卡片、菜单、表格和表单呈现统一的圆角、边框与弱阴影系统。
4. 今天、足迹、趋势和设置四个主页面在 320–430px 上与参考图具有相近的现代、明亮、极简气质。
5. 登录、数据管理和全部记录表单同步完成视觉升级，不出现明显旧样式页面。
6. 现有功能、信息完整性、未知值语义、认证与数据安全边界保持不变。
7. 自动化测试、Lint、类型检查和生产构建通过；规定视口无页面级横向溢出。
